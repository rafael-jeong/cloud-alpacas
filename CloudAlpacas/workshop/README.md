# workshop/ — 오늘의 의사결정 워크숍 (2~3시간)

## 이 폴더는 무엇인가

**이 폴더는 문서가 아니다. 토론판(Discussion Board)이다.**

목표는 딱 하나: **"Salesforce를 가르치는 것"이 아니라 "팀이 함께 결정을 내리는
것".** 우리는 Salesforce가 처음인 Baby Team이고, 오늘 워크숍은 2~3시간 안에
끝나야 한다.

**규칙**
- 페이지 하나는 질문 하나에만 답한다.
- 페이지 하나는 2~3분 안에 이해되어야 한다. 5분 넘게 걸리면 그 페이지는 너무
  복잡한 것이다.
- 모든 페이지는 **큰 그림 → 작은 표 → 팀 논의** 순서만 따른다. 그 이상 없다.
- 자세한 설명, 필드, Flow, Apex, 연동 같은 구현 얘기는 여기 없다 — 전부
  `docs/`에 있다. 오늘 결정이 아키텍처를 바꾸면, 그 다음에 `docs/`를 고친다
  (CLAUDE.md §7).

## 오늘 다루는 4장 (결정용)

이 4장은 위 규칙(질문 하나, 2~3분, 큰 그림→작은 표→팀 논의)을 그대로 따른다.
오늘 회의는 이 4장을 중심으로 진행한다.

| 페이지 | 질문 |
|---|---|
| [`01_Customer_Journey.md`](./01_Customer_Journey.md) | 이 고객 여정이 말이 되나요? |
| [`02_Objects.md`](./02_Objects.md) | 우리에게 어떤 Object가 필요한가요? |
| [`03_ERD.md`](./03_ERD.md) | Object들이 서로 어떻게 연결되나요? (오늘 가장 중요한 페이지) |
| [`04_Tabs.md`](./04_Tabs.md) | 김매니저가 실제로 무엇을 보게 되나요? |

## 참고용 2장 (오리엔테이션 · FAQ)

이 2장은 "결정"이 아니라 "이해"를 돕는 참고 자료다. 한 번에 다 읽는 페이지가
아니라, 필요할 때 펼쳐보는 사전에 가깝다 — 그래서 위 4장의 2~3분 규칙을
그대로 적용하지 않는다.

| 페이지 | 질문 |
|---|---|
| [`05_OBJECT_MAP.md`](./05_OBJECT_MAP.md) | 전체 Object가 도메인별로 어떻게 연결되나요? (5분 오리엔테이션용, ERD 아님) |
| [`06_RELATIONSHIP_GUIDE.md`](./06_RELATIONSHIP_GUIDE.md) | 이 관계들은 왜 이렇게 설계됐나요? (FAQ, "왜"에만 집중) |

Salesforce Mapping, Automation(Flow/Apex/연동/Trigger), 필드 설계 같은 구현
주제는 오늘 워크숍 범위가 아니라서 `docs/03_SYSTEM.md`로 옮겼다 — 궁금하면
거기서 본다.

## 사용법

1. A3로 인쇄하거나 화면에 띄운다.
2. 각 장의 "Team Discussion"에서 나온 결정은 그 자리에서 표에 적는다.
3. 오늘 끝나면: 아키텍처가 바뀐 부분만 `docs/`에 반영한다(전부 다시 쓰지 않는다).
